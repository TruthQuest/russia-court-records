The method behind No Way Out

Who decides Russia's political cases? The courts' own records say.

courtlink links the people OVD-Info documents as politically prosecuted in Russia to their court cases, to the judges who presided, and to international sanctions lists. It reads the courts' public case pages, matches them to OVD-Info's records, and builds everything into a knowledge graph that can be tested as a whole.

01 · The question

OVD-Info knows who was prosecuted. The courts know who judged them.

OVD-Info has documented thousands of people prosecuted in Russia for what they said, wrote or believed: who was charged, under which article, and what happened to them. Its records rarely say which judge decided the case, and they cannot say what the courts handle that no one has reported yet.

Russian courts publish that information themselves. Every court of general jurisdiction keeps a public page for each case, with the case identifier, the presiding judge, every hearing and custody decision, and the result for each defendant. courtlink reads those pages at scale and joins them to OVD-Info's records.

02 · How it works

From a person's record to a judge's name, with a saved page behind every link.

Court case pages

Each court's own website in the sudrf.ru system (GAS "Pravosudie"). Searched by article and registration year; every page saved with its retrieval time and a SHA-256 checksum.

Court directory

About 2,300 court websites by region, from Dataout's sudrfparser (CC BY-SA 4.0).

OVD-Info records

The people, articles, dates and docket numbers to match. Used with permission; never redistributed.

Sanctions lists

OpenSanctions' consolidated EU, UK, US, Ukrainian and other lists, checked against every judge.

Phase 1 starts from OVD-Info's records and looks for each one in the courts. Phase 2, the census, lists every case the courts register under the relevant articles, so OVD-Info's records can be measured against the courts' own total.

Matching without guessing

A docket number is unique only within one court, so it is never enough on its own. Each candidate is scored on docket, surname (the Cyrillic name transliterated and fuzzy-matched), decision date and article, then decided by the first explicit rule that applies. Every link records the rule and its confidence.

RuleEvidenceConfidence
exclusionsdifferent article; a different named defendantreject
R1docket + surname (similarity 90 or more)high
R2docket + article + decision within 7 days of OVD-Info's datehigh
R3docket + decision within 7 dayshigh
R4docket + weaker surname matchmedium
R5docket + articlemedium
R6docket onlylow
R7no docket: surname, plus article and/or datehigh or medium
03 · The knowledge graph

The court case is the hub. Every statement points back to a saved page.

The graph is built against the CourtLink ontology (OWL 2), validated with SHACL, and joined to Trace Origin's wider graph of OVD-Info records. Reasoning uses property chains, defined classes and a closed-world step after inference.

  • The case identifier (УИД) is assigned when the first material reaches a court and follows the case when it is sent elsewhere or refiled, so a case is counted once.
  • Records and cases are linked, not merged. Each link carries the rule and confidence that made it.
  • Judges are posts, not people. The same name at two courts is a possible match (cl:possiblySameAs), never owl:sameAs.
  • Every outcome is dated and classed as terminal (verdict, dismissal, compulsory medical measures) or interim (returned, transferred, pending).
  • Two kinds of article, the one OVD-Info records and the one the court lists, are kept apart so disagreements stay visible.
04 · Analyses

Each method is tested on planted signals before it touches real data.

QuestionMethod
Are cases concentrated among a few judges?Concentration curves per court type; year-stratified Monte Carlo against each court's own assignment; Benjamini–Hochberg correction.
Were related cases handled as a group?A scan over windows of consecutive case identifiers at each court, with receipt dates and a shared article, scored against random placement.
Do some judges' case pages record one uniform sequence?Each case reduced to its recorded events; permutation test within court and article group (1,000 reassignments).
Is dismissal rare because the law forbids it, or because it is not used?Outcomes by article part and gravity, single-charge defendants, decision year, trials in absentia and the recorded grounds of each dismissal.
How complete are OVD-Info's records?The court census against OVD-Info: docket links plus a surname, initial, region, article and date check, with name-match recall measured on docket-linked cases.
Do judges match a sanctions listing?Surname blocking, initials and patronymic checks, and whether the listing describes a judge. Every match is a lead for human review.

06 · Privacy and ethics

Built so the analysis can be shared without exposing anyone.

  • No defendant data in the repository. Every run output goes to a local folder that is never committed. A privacy check blocks any commit or push containing run outputs, OVD-Info's export, a real case-page link or a real case identifier.
  • Names are not written. The census and case-detail steps record counts and roles, never the names of defendants, lawyers or victims.
  • Published outputs omit anything that leads to a person: no case numbers, no case-page links, no small counts. A fuller workbook goes to OVD-Info only.
  • Captchas are solved by a person, on one page, never automatically.
  • Gentle on the courts: one request at a time per court, a pause between requests, and a cache so no page is fetched twice.
  • Judges are named only from the courts' own records, in their official capacity. A sanctions match is a lead, not an identification.
  • Collection code on request only. The code that gathers data from the courts goes to named human rights organisations, journalists and researchers, each copy marked so it can be traced.
  • Report misuse. If you see this code used to identify or target people, write to ebrattin@traceoriginresearch.com. Reports are kept confidential.
07 · Run it

Everything can be tested offline on invented data.

git clone https://github.com/TruthQuest/russia-court-records.git
cd russia-court-records
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
bash scripts/install_hooks.sh
python tests/check_analyses.py
python tests/check_graph_analytics.py

The public repository holds the matching, the knowledge graph, the analyses and their tests, all runnable on synthetic data with no network. A live run needs OVD-Info's export, which is not public, and the data-collection code.

Getting the data-collection code

The code that searches the court websites and downloads case pages, with its end-to-end test and the full operating guide, is available to human rights organisations, journalists and researchers on request: ebrattin@traceoriginresearch.com. Please say who you are, which organisation you work with, and what you want to use it for. Each copy is issued to a named person or organisation and marked so it can be traced.

Limits. A case page shows what the court's staff entered: a missing entry is not a hearing that did not happen. Courts withhold some pages and names. Moscow, magistrate and garrison courts are outside the main search. Links between records and cases are automatic and should be checked by hand on a sample before any figure is cited.
